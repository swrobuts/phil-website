Phil 2026

Today, the technology
finally caught up.

Phil is a working personal information manager — not a concept video. It manages email, calendar, tasks and knowledge using today's AI tools. It does not do everything Apple envisioned. It does what matters most, right now.

Phil reads your inbox and categorises every message: VIP / Action Required / FYI / Noise. Each mail gets a 2-sentence summary and a concrete action recommendation. Powered by LM Studio, Claude, or both — you choose.

Under the Hood

Four technologies
that make Phil work.

Phil is not a wrapper around a chat API. It combines four distinct techniques — each grounded in decades of computer science research.

Retrieval-Augmented Generation

RAG — Answer from your data, not from hallucination

Before generating any response, Phil retrieves the most relevant context from your actual mailbox. Every email is split into chunks, embedded as a 1536-dimensional vector using an embedding model, and stored in ChromaDB. At query time, the question is embedded too — cosine similarity finds the semantically closest chunks.

Only the retrieved chunks enter the LLM's context window. This means Phil's answers are grounded in your real data, not invented from training statistics. It also means the model needs no fine-tuning — retrieval replaces memorisation.

RAG solves the two hardest problems of LLM deployment: hallucination (the model invents facts it doesn't know) and staleness (training data has a cutoff date; your inbox does not).

RDF Knowledge Graph + OWL Ontology

Graph — What vector search cannot see

Vector similarity finds documents that feel related. A knowledge graph finds documents that are structurally connected. Phil maintains an RDF graph of entities extracted from emails: Person, Organisation, Project, Event.

Relationships become directed edges: "Prof. Müller supervises Hausarbeit", "Hausarbeit hasDeadline 15-März". The OWL ontology defines class hierarchies and inference rules — e.g., anyone who emails about a project is automatically classified as a project participant.

SPARQL queries traverse these relationships: who has written about topic X in the last 30 days? Graph reasoning and vector search are complementary — Phil runs both and merges the results.

CO-STAR Prompt Engineering

Structured prompts — Consistency over chance

Every LLM call in Phil is structured using the CO-STAR framework, developed by Sheila Teo (GovTech Singapore, winner of Singapore's first GPT-4 prompt competition, 2023):

Context — background and constraints  ·  Objective — exact task  ·  Style — how to write  ·  Tone — register  ·  Audience — who reads this  ·  Response — output format

Structured prompting reduces hallucination, makes prompts auditable, and ensures consistent JSON output — critical when the response feeds a dashboard tile or a mail category badge. Every Phil prompt is documented in the Prompts page →

Hybrid LLM Architecture

Cloud or local — Phil decides

Phil's LLMClient class wraps both the Anthropic API and LM Studio's local OpenAI-compatible endpoint (localhost:1234/v1). On each request, it checks whether the local server responds within a timeout. If yes — local model, zero latency, zero cost, zero data transmission. If no — transparent fallback to the cloud.

This enables three real deployment scenarios: offline development (local model only, no internet), privacy-critical use (hospital, HR, legal — no data leaves the machine), and production with fallback (local for speed, cloud for reliability).

LM Studio runs as a desktop application and serves any GGUF-quantised model as a REST API. Qwen2.5-32B-Instruct at Q4_K_M quantisation fits in 22 GB of unified memory and produces approximately 22 tokens per second on Apple M4 Pro — sufficient for real-time chat.

Ethics & Law

With great retrieval
comes responsibility.

A system that reads your email, knows your calendar, and remembers facts about you is powerful. It deserves honest reflection — about where it runs, what it stores, and what it means.

DSGVO & Privacy by Design

  • Email content is personal data under DSGVO Art. 4 — processing requires a legal basis
  • Local LLM mode: no data processed on third-party servers → satisfies Art. 25 (Privacy by Design)
  • Cloud mode requires a Data Processing Agreement (DPA) with Anthropic — not included by default
  • All stored memory facts are visible, editable, and deletable by the user (right to erasure, Art. 17)
  • Phil does not send emails autonomously — every action requires explicit user confirmation

EU AI Act (in force August 2024)

  • LLM personal assistants = Limited Risk under the EU AI Act — not high-risk
  • Art. 50: Transparency obligation — users must know they interact with an AI system
  • Phil's UI clearly labels all AI-generated responses and summaries
  • If the system performs user profiling (predictive modelling of behaviour), classification shifts to High-Risk with full conformity requirements
  • Full compliance deadline for most provisions: August 2026 — this project is ahead of schedule

Societal & Career Impact

  • Knowledge retrieval is becoming instant and free — the advantage shifts from access to judgment
  • Augmentation, not replacement: Licklider's 1960 vision of Man-Computer Symbiosis, finally realised
  • New skills required: prompt engineering, critical evaluation of AI output, system architecture literacy
  • The productivity gains are real — and unevenly distributed. Who gets access to these tools matters
  • Building Phil is more valuable than using it: you understand the black box by constructing it

Academic integrity note: Phil is a tool for information management, not for generating academic work. The ability to build such systems is a technical skill. The ability to evaluate them critically — to ask who controls them, what biases they carry, and what they optimise for — is more valuable still.

For Students

Rebuild Phil
yourself.

Python 3.11+ and Node 20+, or Docker Compose for a one-command start. An Anthropic API key and a Google Workspace account are required either way.

DE: Python 3.11+, Node 20+ und ein Anthropic API-Key — oder alternativ Docker Compose für einen Ein-Befehl-Start. Auch ein Google Workspace Konto wird benötigt.
1

Clone & install

Get the code and install Python and JavaScript dependencies.

git clone https://github.com/swrobuts/phil-knowledge-navigator
pip install -r backend/requirements.txt
cd frontend && npm install
2

Configure .env

Copy the example file and add your API key. Only ANTHROPIC_API_KEY is required to start.

cp backend/.env.example backend/.env
# Add ANTHROPIC_API_KEY=sk-ant-...
DE: Die .env.example erklärt jeden Parameter. Für den Start reicht der Anthropic API-Key.
3

Run Phil locally

Start backend and frontend in two terminals.

# Terminal 1 — Backend
uvicorn backend.main:app --reload

# Terminal 2 — Frontend
cd frontend && npm run dev

# Open → http://localhost:5173
OR

Run with Docker Compose

Prefer containers? One command starts backend, frontend and Traefik together.

cp backend/.env.example backend/.env
# Add your API key and Google credentials
docker compose up --build
DE: Docker Compose startet alle Dienste gebündelt. Ideal für reproduzierbare Umgebungen und den Einsatz auf eigenen Servern oder in der Cloud.

Fazit

The gap has closed.
Now it's your turn.

In 1987, Apple made a 9-minute film about what computing could become. The assistant was called Phil. They couldn't build it — not because they lacked imagination, but because the technology didn't exist yet.

In 2026, a student project at THWS built Phil with open-source models, a free API account, and a semester's worth of curiosity. It reads email. It prepares meetings. It remembers. It speaks. It runs entirely locally — with zero data leaving your machine.

What took Apple a billion-dollar research budget and a concept video in 1987 now takes a few weeks and an internet connection. That should change how you think about what you are capable of building.
